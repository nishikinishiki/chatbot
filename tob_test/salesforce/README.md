# tob_test / salesforce

元の `/tob/salesforce/` は変更しない、別ディレクトリのフォーム実装です。

## UI仕様
- PC：左65%、右35%を基本とする2カラム。左の訴求画像領域は独立スクロール。右も画面高を超える場合に限りスクロールします。
- 画面幅901〜1130px：左61%、右39%。900px以下：画像とフォームを縦並びに変更。
- 訴求画像：`/common/images/test.jpg`（ユーザーがリポジトリに追加済み）。縦長画像全体をトリミングせず表示。
- 入力フォームは3ステップで横スライド遷移。ブラウザの戻るボタンではなくフォーム内の「前の画面に戻る」を使用し、入力値を維持します。
  1. 基本情報：姓・名、電話番号、メールアドレス（ブラウザのオートコンプリート対応）
  2. 年収・年齢：単一選択のボタン
  3. 関心テーマ：単一選択のボタン、投資経験：複数選択ボタン（「特になし」は排他的）、個人情報取扱いへの同意
- 続く画面では第1・第2希望日時を入力し、その他時間の場合は自由入力欄を表示。
- Salesforce固有の既存の質問項目と値を踏襲。

## Google Tag Manager
既存コンテナ `GTM-TCL9ZH6` を読み込みます。以下のイベントのみ dataLayer にpushします。

| event | 主なパラメータ | 意味 |
| --- | --- | --- |
| `form_step_view` | `form_variant`, `step_number`, `step_name` | 3ステップそれぞれの表示 |
| `form_step_complete` | 同上 | 必須項目の検証を通過して次へ進んだ |
| `form_step_validation_error` | 同上 | 当該ステップの入力検証エラー |
| `form_appointment_view` | `form_variant` | 希望日時入力画面の表示 |
| `form_details_review_complete` | `form_variant` | 第2段階の入力検証通過 |

これらは **実際のリード獲得CVではありません**。GAS送信をこの実装では有効化していないため、`chat_form_submission_success` や `lead_attributes_ready` は送信していません。電話番号・氏名・メールアドレスなどの個人情報はdataLayerに送信しません。GTMコンテナ内の既存タグは、ページビュー等により通常どおり発火する可能性があります。

## 本番送信の有効化に必要な作業
現行GASの入力キー、送信成功・失敗判定、会話後半の追加入力、CVイベントの発火条件、個人情報の取扱いを別途検証した上で有効化すること。GAS送信がない状態でリード成功CVを発火させないこと。

編集対象はこの `tob_test/salesforce/` フォルダ内の4ファイルのみです。
